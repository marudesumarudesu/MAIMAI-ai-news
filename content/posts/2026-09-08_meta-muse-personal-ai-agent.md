# Meta「Muse」公開｜メール送信・旅行予約・決済まで動く個人AIエージェント、Secure VMとSentinelで何を守るのか

## 3行でいうと

- Metaは2026年9月8日、個人向けAIエージェント**「Muse」**を米国で公開しました。質問に答えるだけでなく、専用ブラウザを使ってWebを操作し、メール送信、フォーム入力、旅行予約、買い物、長期タスクの継続実行まで行います。
- Museはユーザーごとの**Muse Secure VM**上で動き、別系統の「Sentinel」エージェントが外部通信を監視します。パスワードや決済情報はMuse自身から見えない領域に保存し、メール送信や購入など取り消しにくい操作ではユーザー承認を挟む設計です。
- ただし現時点の提供地域は**米国のみ**で、日本提供日は未発表です。Reutersは社内テストで接続断、意図しないデータアップロード、個人写真が露出するセキュリティ問題が報告されたと伝えており、Metaの公式説明だけで安全性を評価する段階ではありません。

## 何が発表された？

Metaは2026年9月8日、個人向けAIエージェント「Muse」を発表し、米国でiOS、Android、muse.aiへの展開を開始しました。WhatsAppからも会話でき、AIグラスへの対応も今後予定されています。

Museを動かす基盤モデルは**Muse Spark**です。Meta Superintelligence Labsが開発したモデルで、Metaは自社で最も高性能なモデルと説明しています。

Museの特徴は、チャット画面で回答を返して終わらない点です。専用のクラウドコンピュータを持ち、その中でブラウザ、ファイルシステム、ターミナルを利用します。

Metaの設計資料では、Museは次の操作ができます。

| 機能 | Museで可能なこと |
|---|---|
| Web操作 | 検索、Webページ移動、フォーム入力 |
| メール | 内容確認、権限があれば送信 |
| 旅行 | 検索、予約 |
| 買い物 | 商品検索、チェックアウト |
| 決済 | Stripe Linkを利用した代理決済 |
| 長期タスク | アプリを閉じた後もバックグラウンド継続 |
| 記憶 | 会話や目標から長期的な情報を保持 |
| 成果物 | 文書、PDF、Webページ、ダッシュボード等を生成 |
| プロアクティブ動作 | ユーザーから質問されなくても必要時に通知 |

Metaは「free for most of what people need」と説明しており、多くの用途は無料で提供するとしています。一方、より多く利用するユーザー向けに有料サブスクリプションを予定しています。

2026年9月8日時点で、その具体的な価格は公表されていません。

## 今までと何が違う？

一般的なAIチャットは、ユーザーが質問し、AIが回答を返す「1往復」が基本です。

Museは一つの長い会話を維持しながら、複数の仕事を同時に受け取り、裏側で作業を続けます。

| 項目 | 一般的なAIチャット | Meta Muse |
|---|---|---|
| 基本動作 | 質問への回答 | タスクの実行 |
| ブラウザ操作 | 製品により対応 | 専用ブラウザで対応 |
| フォーム入力 | 限定的 | 対応 |
| メール送信 | 連携次第 | 権限設定後に対応 |
| 購入・決済 | 限定的 | Stripe Linkで対応 |
| アプリ終了後 | 通常は停止 | バックグラウンド継続 |
| 長期記憶 | 製品ごとに異なる | 目標・会話を継続利用 |
| 自発通知 | 限定的 | 状況に応じて可能 |
| 実行環境 | サービス内 | ユーザーごとのSecure VM |

設計上、特に大きいのが「自分専用のコンピュータを持つ」点です。

Muse Secure VMはユーザーごとに分離された仮想マシンで、Museのブラウザや接続済みサービスの情報が置かれます。

さらに同じVM内に、Museとはシステムレベルで分離された**Sentinel**という別エージェントが存在します。Metaによれば、Museからインターネットへ出る通信はSentinelが確認し、必要ならユーザー承認を求めます。

つまり、作業を実行するAIと、その行動を監視するAIを分けた構成です。

## これで何ができる？

### 1. 旅行計画を「検索」で終わらせず予約まで進める

例えば、

> 10月16日から東京発で3泊。ニューヨークでホテルを探して。1泊300ドル以内、地下鉄駅徒歩5分以内。候補を比較して、条件が一番良いものを予約直前まで進めて。

と依頼します。

Museはブラウザを使って候補を調べ、フォーム入力まで進められます。購入・予約など重要操作では承認を求める設計です。

### 2. 学校・仕事のメールから予定を拾い続ける

Metaの設計担当者は、学校から届く多数のメールやWebサイトをMuseに確認させ、重要日程をカレンダーへ追加させた利用例を紹介しています。

実務では、

> 営業チーム宛てのメールを確認し、日程変更、提出期限、顧客からの宿題だけを整理して。必要な予定はカレンダー登録候補にして。

といった使い方が考えられます。

### 3. 買い物を代理で進める

MuseはStripeのLinkを使った決済に対応します。

StripeのAIエージェント向けLinkでは、AIへ本物のカード情報を渡さず、**タスクごとに1回だけ使えるカード**を発行します。決済自体もユーザー承認が必要です。

例えば、

> 15インチPCが入る黒いリュックを150ドル以下で探して。防水、返品無料を優先。条件を満たす中で評価が高いものをカートに入れて。

という指示を出し、最終購入だけ自分で承認する形です。

### 4. 長期目標を継続的に管理する

MuseにはGoals機能があり、数週間・数か月単位の目標を追跡できます。

「来年4月までに10km走れるようにする」と設定し、予定変更や進捗を見ながらトレーニング計画を修正するといった使い方です。

Museは関連情報に変化があると、ユーザーから質問されていなくても通知できます。

## 誰に関係ある？

### 個人ユーザー

影響が最も大きい層です。

メール、買い物、旅行、カレンダーなどをAIへ渡したい人には、従来のチャット型AIより利用範囲が広がります。

一方、メールや個人アカウントをAIへ接続したくない人には向きません。

### 企業

現時点のMuseは個人向け製品です。

企業利用では、従業員が業務メールや社内サービスを個人Museへ接続してよいか、情報管理ルールを先に決める必要があります。

会社が許可していないSaaSへ顧客情報や社内データを渡す運用は避けるべきです。

### 開発者

Museそのものは、9月8日時点では一般開発者向けAPIとして発表されていません。

そのため、「Museを自社アプリへAPI組み込みする」使い方は現時点では公開されていません。

### 日本ユーザー

現時点では**米国のみ**です。

日本での提供開始日、料金、日本語固有の対応範囲、日本国内で接続できる金融・ECサービスなどは未発表です。

日本ユーザーは今すぐMuseを標準的に利用できる状況ではありません。

## 実際の使い方

米国で利用可能なユーザーは、Museアプリまたはmuse.aiから始めます。

Museでは、最初から大量の権限を与える必要はありません。Metaの公式説明でも、メールの場合は「読むだけ」「送信も許可する」といった権限を利用者が選べます。

最初は読み取り中心にする方が安全です。

例えば、

> メールを読んで、今週中に対応が必要なものを一覧にしてください。  
> メール送信、削除、外部へのファイルアップロードは行わないでください。

次に、限定した書き込みを許可します。

> 次の返信文を下書きしてください。送信はしないでください。  
> 宛先、件名、本文を表示して、私が確認してから送信してください。

買い物では、

> 条件に合う商品を3つ選び、価格、返品条件、送料を比較してください。  
> カート追加までは許可しますが、購入は必ず私の承認を求めてください。

のように、どこまで自動実行してよいかを明確にします。

MetaはUI側にも承認カードを用意し、メール送信や購入など「取り消しにくい操作」では確認を挟む設計にしています。

## 注意点

### 日本ではまだ使えない

9月8日の公式発表では米国展開のみです。

日本提供時期を推測して案内することはできません。

### セキュリティ機構があっても事故リスクは残る

MetaはSecure VM、Sentinel、資格情報の分離、承認カード、監査ログなどを用意しています。

一方、ReutersはMuseの社内テストで、接続が切れる、意図しないデータアップロードが発生する、個人のiCloud写真が露出するなどの問題が報告されたと伝えています。

MetaはReutersに対し、Museが安全性とプライバシー基準を満たしていると説明していますが、個別のテスト事故について詳細回答していません。

したがって、「Secure VMがあるから安全」と断定することはできません。

### 長期記憶には利便性とリスクの両方がある

Museは会話の中で一度伝えた好みや家族・友人に関する情報を記憶し、後から提案に利用できます。

ユーザーは特定情報を「忘れて」と指示できます。

ただし、長期記憶へ何を保存するかは慎重に考える必要があります。会社のパスワード、秘密鍵、医療情報、本人確認情報などを会話本文へ直接書き込む運用は避ける方が安全です。

### AIがパスワードやカード番号を見る設計ではない

Metaによれば、接続サービスの認証情報や決済情報はSecure Storageへ保存され、Museモデルからは見えません。

Stripe Linkも使い捨てカードを発行し、本物のカード情報をAIに開示しない方式です。

これは重要な安全策ですが、AIが誤った商品や相手を選ぶ「判断ミス」まで防ぐものではありません。

### 広告システムとの分離と学習利用は別

Metaは、Museの会話とSecure VM内データを広告システムへ共有しないと説明しています。

また、利用者はMuseとのやり取りをMetaのAIモデル学習に使わせない選択もできるとしています。

「広告に使わない」と「モデル学習に使わない」は別設定なので、プライバシーを重視する利用者は両方を確認する必要があります。

### Confidential VMはまだ提供前

Metaは2026年後半に**Muse Confidential VM**を導入予定としています。

これはVM全体を利用者だけが持つ鍵で暗号化し、Meta自身も中身へアクセスできない構成を目指すものです。

9月8日時点のMuseにすでに搭載されている機能ではありません。

## MAIMAIの評価

**重要度：98 / 100**

ここからはMAIMAIの評価です。

### 一般ユーザー：100点

個人向け生成AIの利用方法を大きく変える可能性がある発表です。

重要なのはチャット性能より、AIがブラウザ、メール、決済、カレンダーなどへ接続し、人間がアプリを閉じても仕事を続ける点です。

ユーザーは「AIに質問する人」から、「AIへ仕事を割り当て、必要な部分だけ承認する人」へ役割が変わります。

### 企業：91点

Muse自体は個人向けですが、企業にも強い影響があります。

従業員が個人AIエージェントへ会社のメールや業務SaaSを接続するケースが増えると、企業は「生成AIへの入力禁止事項」だけでは足りません。

今後は、

- どのAIが会社アカウントへログインしてよいか
- 読み取りと書き込みのどちらを許可するか
- 決済・メール送信・ファイルアップロードを許すか
- 監査ログをどう残すか

までポリシー化する必要があります。

### 日本市場：93点

現在は米国限定なので、日本への即時影響はありません。

それでも重要度は高いです。MetaはWhatsApp、Instagram、Facebook、AIグラスを持っており、既存サービスとの接点が非常に多い企業です。

日本展開時には、個人向けAIエージェントが一部の技術者だけのツールではなく、一般消費者へ一気に広がる可能性があります。

### 競争環境：100点

OpenAI、Anthropic、Googleもエージェント機能を強化しています。

MuseでMetaが打ち出した競争軸は、モデルのベンチマーク順位だけではありません。

**専用VM、長期記憶、バックグラウンド実行、決済、権限管理、監視用の別エージェントまでを1つの消費者向け製品にまとめたこと**が重要です。

MAIMAIとしては、2026年の個人向けAI市場で特に重要な製品発表の一つと評価します。

一方、メール・写真・決済・Web操作まで任せるエージェントでは、1回の誤動作がチャットの誤回答より大きな被害につながります。Museの競争力は「何ができるか」だけでなく、実利用でSecure VMとSentinelがどの程度事故を防げるかで評価すべきです。
