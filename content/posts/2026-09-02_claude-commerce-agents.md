# Claude Commerce Agents公開｜買い物AIと店舗運営AIの設計図をオープンソース化。EC企業への実務インパクト

## 3行でいうと

- Anthropicは2026年9月2日、**Claude Commerce Agents**を公開しました。顧客向けの「Shopping Agent」と、事業者向けの「Merchant Agent」を、動く参照実装・安全設計・Claude Codeプラグイン込みで公開しています。
- 対応例は小売、旅行、通信、エンタメの4業種。Messages API、Claude Agent SDK、Claude Managed Agentsの3方式で構築でき、AWS Bedrock、Google Cloud Vertex AI、Microsoft Foundryでも展開できます。
- 重要なのは、AIが勝手に決済や価格変更を実行する設計ではない点です。**購入は既存チェックアウトへ引き渡し、店舗側の変更操作は人間承認まで保留する**構成が最初から入っています。

## 何が発表された？

Anthropicは2026年9月2日、ECや予約サービス向けAIエージェントの開発用ブループリント「Claude Commerce Agents」を公開しました。

「ブループリント」は、完成サービスをそのまま契約する製品ではありません。企業が自社システムへAIエージェントを組み込むための、**コード、プロンプト、ツール設計、安全ルール、デモ、Claude Codeプラグイン**をまとめた参照実装です。

公式GitHubリポジトリには、大きく2種類のエージェントが含まれています。

| 種類 | 対象 | 主な役割 |
|---|---|---|
| Shopping Agent | 顧客 | 商品検索、比較、複数商品提案、カート作成、注文・返品案内 |
| Merchant Agent | 店舗・運営担当 | 売上分析、在庫監視、価格・販促提案、商品情報修正、キャンペーン下書き |

対応デモは小売、旅行、通信、エンタメの4業種です。コードはApache License 2.0で公開されています。

実行方式も1つに固定されていません。Claude Messages API、Claude Agent SDK、Claude Managed Agentsで構築でき、Amazon Bedrock、Google Cloud Vertex AI、Microsoft Foundryなどでも展開できます。

## 今までと何が違う？

これまで企業が「商品を探して、比較して、カートへ入れるAI」を作ろうとすると、モデルAPI以外の部分をかなり自作する必要がありました。

必要になるのは、商品検索、顧客認証、在庫確認、注文情報取得、カート操作、返品ポリシー参照、ツール呼び出し制限、誤操作を防ぐ承認処理、会話履歴の保存などです。

Claude Commerce Agentsでは、こうした構造が参照コードとしてまとまっています。

| 操作 | 参照実装の扱い |
|---|---|
| 商品検索 | AIが実行可能 |
| 商品比較 | AIが実行可能 |
| カート作成 | AIが支援 |
| 決済 | AIが直接実行せず、既存チェックアウトへ引き渡し |
| 在庫・商品情報変更 | 変更案を作成 |
| 価格・販促変更 | 変更案を作成 |
| 店舗側の書き込み操作 | 人間承認までステージング |

「ステージング」とは、変更をすぐ本番反映せず、承認待ちの状態に置くことです。

Anthropicの公式GitHubでは、デモに認証機能は含まれておらず、実際の企業導入では認証、権限、決済、法令対応を企業側で実装する必要があることも明記されています。

Anthropicは公式ブログで、Claude上のshopping agentsを使っている小売企業では、カート金額が最大35%大きく、購入完了率が60%高い事例を紹介しています。ただしこれはAnthropicの顧客事例ベースの公表値であり、業界平均や独立した第三者試験ではありません。

## これで何ができる？

### 1. 商品を自然文で探すECサイト

顧客が「黒で、雨の日でも使えて、2万円以下の通勤用リュック。PCは15インチ」と入力すると、商品カタログから条件に合う候補を探し、違いを比較し、カートまでつなげる仕組みを作れます。

### 2. 旅行商品の比較・旅程作成

travelデモでは、日付付き在庫を扱いながら旅行商品を比較して旅程を組み立てる構成があります。「10月10日から2泊、東京発、子ども1人を含む3人、移動込み20万円以内」といった複数条件を会話から処理できます。

### 3. 店舗担当者向けの在庫監視

Merchant Agentでは「来週のセール前に在庫切れしそうな商品は？」と質問し、在庫や販売ペースを基に候補を抽出する設計ができます。

### 4. 販促キャンペーンの下書き

売上・在庫データを基に、値引き対象候補、キャンペーン対象、商品訴求案、マーケティング文面を作成できます。

## 誰に関係ある？

### 個人ユーザー

一般のClaudeユーザーが追加機能としてONにするものではありません。今後、ECや予約サービスの検索画面が会話型AIへ変わる可能性が高まる点が利用者側の影響です。

### EC・小売企業

最も関係があります。商品点数が多い、検索条件が複雑、顧客から同じ質問が多い、在庫・価格判断に時間がかかる企業では検証価値があります。

### 旅行・通信・チケット企業

Anthropicが公式参照実装を用意した4業種に含まれています。旅行では日付在庫、通信では料金プラン、エンタメでは座席・チケットなど、通常のECより条件が複雑な取引にも対応する設計例があります。

### 開発者

Claude Codeプラグインが用意されています。

```text
claude plugin marketplace add anthropics/commerce-agents
claude plugin install commerce-builder@claude-commerce-agents
```

その後、Claude Codeで次のようにひな型を作れます。

```text
/scaffold-commerce-agent a shopping assistant for our store
```

### 日本企業

技術的には日本のECでも利用できます。ただし、特定商取引法表示、価格表示、返品条件、個人情報、決済、ポイント制度、会員ランクなどは参照実装だけでは完成しません。

日本向け導入では、AI性能に加え、既存ECデータと業務ルールをどこまで正確にAPI化できるかが重要です。

## 実際の使い方

最初から決済まで作る必要はありません。

Anthropic自身もGitHubで、小さく始める方法を案内しています。

Shopping Agentではまず、

1. 商品検索
2. 商品詳細取得
3. 商品比較

だけを接続します。

カート、決済、返品処理はOFFにしても構いません。

例えば、

> 当社の商品DBから、30代男性向け・予算1万円以下・プレゼント用途の商品を3つ提案してください。  
> 在庫切れ商品は除外。  
> 推薦理由は商品データに存在する情報だけを使ってください。

と試します。

確認すべきKPIは、正しい商品を選べた割合、存在しない商品を答えた割合、1回答の時間、APIコスト、従来検索より購入候補が見つかるかです。

店舗側では、最初から価格変更権限を与えず、売上分析、在庫状況、商品情報確認、異常検知だけを許可します。書き込み系ツールは無効にしたままでも利用できます。

## 注意点

### 完成品のSaaSではない

Anthropic公式FAQでは、Claude Commerce Agentsは**open reference implementation**であり、Anthropicが保守する製品ではないと明記されています。企業がforkして自社で管理し、SLAもありません。

### 決済システムではない

参照実装でAIがカード決済を直接行うわけではありません。checkoutは既存の決済画面や外部決済URLへ引き渡す設計です。

### デモには認証がない

GitHubのREADMEでは、サンプルに認証が含まれていないと明記されています。本番環境では顧客ID、セッション、店舗担当者権限、API認証、管理者権限を企業側で実装する必要があります。

### AIへ価格変更を全面委任しない

公式設計では、Merchant Agentの書き込み操作は人間承認まで保留されます。価格、返金、在庫、販促、顧客情報を扱う処理では、この考え方を維持した方が安全です。

### 効果数字をそのまま事業計画に使わない

「カート最大35%増」「購入完了率60%増」はAnthropicによる顧客事例です。自社ECでA/Bテストを行い、売上だけでなく返品率、問い合わせ件数、粗利率も確認する必要があります。

### 日本市場：90点

日本のEC企業でも応用できます。

日本企業では商品マスター、在庫DB、顧客DBが古いシステムに分散しているケースがあります。AIモデルの性能より、データ整備・API化・権限設計が導入スピードを左右する場面も多いと考えます。
