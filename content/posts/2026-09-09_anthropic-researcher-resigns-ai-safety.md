# Anthropic研究者が辞任、AI安全性を公然批判｜「10年以内に人類滅亡10%超」発言とAnthropicの公式安全策を分けて検証

## 3行でいうと

- Anthropic研究者のJacob Coxon氏が2026年9月8日に辞任し、OpenAIとAnthropicが自己改善型の超知能開発を急ぎ過ぎていると公に批判しました。Coxon氏は直前までOpenAIとAnthropicで約3年間、基盤モデルの事前学習研究に携わっていました。
- Anthropicのアラインメント研究チームを率いるEvan Hubinger氏も、将来の超知能による人類規模の破局リスクを「今後10年で10%超」と個人的に見積もり、超知能のalignmentを解決する具体的な計画はまだないと投稿しました。一方で、**現在のモデルのリスクは低い**とも明確に区別しています。
- Anthropic公式は8月のRisk ReportやResponsible Scaling Policyで、強力なAIによる破局的リスクを想定し、能力評価・セキュリティ・開発ペース調整を進めています。今回の重要点は「現在のClaudeが危険」という話ではなく、**研究者自身が将来モデルの制御方法と開発競争の速度に十分な確信を持てていないことが表面化した**点です。

## 何が発表された？

今回の発端はAnthropicの新製品発表ではありません。

2026年9月8日、研究者Jacob Coxon氏がAnthropicを辞任し、X上で理由を公表しました。Financial Times、The Verge、ABC Newsなど複数の報道機関が本人の投稿を確認しています。

Coxon氏は過去約3年間、OpenAIとAnthropicでAIモデルのpretraining、つまり大量データを使って基盤能力を学習させる工程の研究に従事していました。

同氏の主張は大きく3点です。

1. OpenAIとAnthropicは自己改善型AIの開発競争を進めている
2. 将来モデルの危険性に対して、十分に安全な開発条件が整っていない
3. 競争を理由に各社が開発速度を落とせない構造自体が問題

ここで重要なのは、これらは**Coxon氏個人の評価**であり、Anthropicの公式見解そのものではないことです。

一方、Anthropicのalignment研究チームを率いるEvan Hubinger氏はCoxon氏の投稿に反応し、自身は「今後10年以内にAIが全人類を死滅させる確率を10%超と見積もる」と述べました。

Hubinger氏は同時に、Anthropicが努力していると評価しつつ、超知能のalignmentを解決する具体的な計画はまだなく、明確に解決へ向かっている状態でもないと説明しています。

ただし、同氏は追加投稿で**現在のモデルについてはリスクが低いと考えている**と補足しました。

この区別は非常に重要です。

「Claudeを今日使うと人類滅亡リスクが10%ある」という意味ではありません。

## 今までと何が違う？

AI安全性への懸念自体は新しくありません。

Anthropicは創業時からAI safetyを前面に出し、Responsible Scaling Policy（RSP）という内部ルールを公開しています。

今回異なるのは、**社内の現役・直近の研究者が、会社の安全策が将来の超知能に十分かどうかについて公然と強い懸念を示したこと**です。

| 項目 | Anthropic公式方針 | Coxon / Hubinger氏の問題提起 |
|---|---|---|
| 現在モデル | リスク評価と安全策を実施 | Hubinger氏も現在モデルのリスクは低いと説明 |
| 将来モデル | RSPで能力増加に応じて安全策を強化 | 超知能alignmentの解決計画がまだないと懸念 |
| 開発速度 | 必要なら安全性を優先しペース調整 | 競争圧力で十分に減速できないと批判 |
| 自己改善AI | automated R&Dを重要リスクとして監視 | 進展速度が予想より速いと懸念 |
| セキュリティ | 隔離環境、監視、評価強化を進める | 将来能力に対して十分か疑問を提示 |

AnthropicのRSPは2026年7月にVersion 3.4へ更新され、**automated R&Dの閾値**を見直しています。

automated R&Dとは、AIがAI研究やソフトウェア開発を自動化し、それによって次のAIモデル開発自体を高速化する状態です。

さらにAnthropicは8月、最新Risk Reportを公開し、破局的リスクに関する現在のモデル能力、準備状況、緩和策を説明しています。

Anthropic公式のFrontier Safety Roadmapでは、2026年9月30日を目標に、

- 高度に隔離されたネットワークの試作検討
- モデル出力が特定の重みに由来することを証明する「provable inference」
- 強力な攻撃者を想定したセキュリティ強化

などを進めています。

つまり、安全対策をしていない企業という整理も正確ではありません。

問題は、**その対策が将来の自己改善型超知能に間に合うか**という不確実性です。

## これで何ができる？

今回、ユーザーが新しく利用できるClaude機能はありません。

実務的に重要なのは、企業が「AIエージェントへどこまで権限を与えるか」を見直す材料になることです。

### 1. AIエージェントの書き込み権限を分離する

例えば社内AIに、

> 顧客データを分析して、更新が必要なCRMレコードを一覧化してください。

までは許可しても、

> そのまま全件更新してください。

は人間承認を必須にします。

AIの判断性能が高くても、誤動作したときの被害が大きい操作は読み取りと書き込みを分けるべきです。

### 2. AIがAIを改修する処理に上限を置く

開発企業では、コーディングエージェントが自分でコードを書き、テストし、再修正するループが増えています。

例えば、

> テストが通るまで自律的に修正してよい。ただし最大10回まで。外部ネットワーク接続は禁止。新規APIキー作成は禁止。本番デプロイは禁止。

のように、回数・ネットワーク・権限を制限します。

### 3. 「高性能だから任せる」判断をやめる

企業が確認すべきなのはベンチマーク順位だけではありません。

- AIが外部へアクセスできるか
- 何を書き換えられるか
- 誰の承認が必要か
- 失敗時に自動停止できるか
- 操作ログが残るか
- 他のAIエージェントへ権限を委譲できるか

まで確認する必要があります。

## 誰に関係ある？

### 個人ユーザー

現在Claudeを文章作成、要約、調査に使っている人が利用をやめる必要があるという情報ではありません。

Hubinger氏自身も現行モデルのリスクは低いと説明しています。

一方、Claudeや他社AIへメール送信、購入、ファイル削除、外部サービス操作などの権限を与えている人は、承認設定を確認する価値があります。

### 企業

最も関係があります。

企業向けAIは「回答するチャット」から、CRM更新、コード変更、顧客対応、決済、インフラ操作を行うエージェントへ移っています。

能力が上がるほど、事故時の影響範囲も広がります。

### 開発者

AIがAI開発を支援する割合が高い開発チームには重要です。

Anthropic自身がautomated R&DをResponsible Scaling Policyの重要リスクとして追跡しています。

コーディングエージェントを使う場合は、sandbox、ネットワーク制限、秘密情報へのアクセス制御、最大実行回数などを設計した方が安全です。

### 日本ユーザー

今回の辞任自体に日本固有の提供変更はありません。

ただし、日本企業でもClaude Code、AIエージェント、MCP連携の利用が広がっているため、安全設計は共通課題です。

## 実際の使い方

新機能ではないため、今回のニュースを受けて試す専用画面やAPIはありません。

企業でできる具体策は、既存AIエージェントの権限棚卸しです。

例えば次の表を作ります。

| 操作 | AI単独 | 人間承認 | 禁止 |
|---|---:|---:|---:|
| 社内文書検索 | ○ |  |  |
| メール下書き | ○ |  |  |
| メール送信 |  | ○ |  |
| CRM閲覧 | ○ |  |  |
| CRM更新 |  | ○ |  |
| 本番コード変更 |  |  | ○ |
| 決済 |  | ○ |  |
| APIキー発行 |  |  | ○ |
| 外部ファイルアップロード |  | ○ |  |

次に、「AIが自分で判断して次のツールを呼ぶ」エージェントでは、実行回数にも上限を設けます。

例えば、

> このタスクでは最大8回までツールを利用できます。  
> 外部送信、削除、購入、本番変更は実行せず、必要な場合は人間承認を要求してください。  
> 想定外のページ、認証要求、権限エラーが出た場合は停止してください。

といった制御をシステム側にも入れます。

プロンプトだけで安全性を保証するのではなく、API権限やネットワーク側でも制約することが重要です。

## 注意点

### 「10%超」はAnthropic公式の確率ではない

10%超という数字はEvan Hubinger氏個人の見積もりです。

Anthropicが企業として「10年以内の人類滅亡確率は10%」と発表したわけではありません。

### 現在モデルと将来の超知能を混同しない

Hubinger氏は現在モデルのリスクは低いと説明しています。

今回の懸念は、自己改善能力を持つ将来システムに対するものです。

### Anthropicは安全策を公開している

AnthropicはResponsible Scaling Policy、Risk Report、Frontier Safety Roadmapを公開しています。

そのため「安全策が存在しない」という表現も正確ではありません。

争点は、それらが将来能力の進歩速度に対して十分かどうかです。

### 辞任理由の中心部分は本人発言

Anthropicは2026年9月9日時点で、Coxon氏の辞任理由について公式声明を出していません。

本記事では、辞任と本人発言についてFinancial Times、The Verge、ABC Newsなど複数報道で確認しました。

### 破局的リスクの確率は科学的に確定した値ではない

超知能がいつ実現するか、どの程度のリスクがあるかには専門家間でも大きな意見差があります。

10%という数字を統計的に実測された確率として扱うべきではありません。

### 一般ユーザー：80点

今日のClaudeが危険になったというニュースではありません。

ただし、AIが単なる会話相手から、メール送信、コード変更、ブラウザ操作などを行うエージェントへ変化しているため、安全性の議論は一般ユーザーにも関係します。

### 企業：96点

企業への重要度は高いです。

AI導入の評価では「精度」「価格」「速度」が注目されますが、実行権限を持つエージェントでは**誤った行動をしたときにどこまで被害が広がるか**も同じレベルで測る必要があります。

企業が今やるべきなのは、超知能の到来時期を予測することではありません。

現在のAIエージェントに与えている権限を確認し、人間承認、自動停止、監査ログ、ネットワーク制限を入れることです。

### 日本市場：88点

日本企業ではAIエージェント導入が始まった段階であり、まだ権限設計が固まっていない会社も多いと考えられます。

本格導入前に安全設計を入れられる点では、海外企業より後発であることが利点にもなります。

### 競争環境：97点

今回のニュースで最も重要なのは、AI企業同士の競争が安全判断に影響を与える可能性を、現場研究者が公然と問題提起したことです。

Anthropic自身も公式文書で「race-to-the-bottom dynamics」、つまり企業同士の競争によって安全基準が下がる構造を問題として認識しています。

同社は9月初めの公式発表で、業界全体に合法的で検証可能な開発ペース調整の仕組みが必要だと明言しました。

MAIMAIとしては、今回の辞任だけを根拠にAnthropicの安全性を否定的に断定するのは適切ではないと評価します。

同時に、Anthropic自身の安全研究責任者が「超知能alignmentの解決計画をまだ持っていない」と公言した点は重く見るべきです。

今後の評価材料は、発言の強さではなく、Anthropicが9月30日までに予定している安全研究の進捗、Responsible Scaling Policyの運用、次世代モデル公開時の能力評価と安全策です。
